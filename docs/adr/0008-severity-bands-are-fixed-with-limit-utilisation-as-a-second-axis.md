# Severity is fixed dollar bands, with limit utilisation as an independent second axis

`severity_band` derives from the settled claim amount on documented half-open cuts — minor `[0, 2500)`, moderate `[2500, 10000)`, severe `[10000, 50000)`, catastrophic `[50000, ∞)`. "High-severity" means `severity_band IN ('severe','catastrophic')`. `limit_utilization_pct` and `at_or_near_limit` are carried as a separate axis and are never folded into the band.

Percentile bands recompute on every regeneration, so "high-severity claims" would return a different set week to week — breaking through the back door the demo reproducibility that ADR-0006's seed-owns-identity rule exists to guarantee. Utilisation-only severity stops correlating with dollars, so a $900 claim against a $1,000 limit would outrank a $180,000 liability loss and every portfolio question about large claims would return small ones. Dropping bands entirely would make "which changes precede high-severity claims" — one of the four MVP capabilities — unanswerable without the user inventing a threshold.

## Consequences

- **The cuts are a generator contract, not an empirical claim.** We control the claim-amount distribution, so it is designed around the cuts rather than the cuts justified against real actuarial data. The generator must produce meaningful populations in every band including catastrophic, and must place deterministic scenario claims in known bands by construction rather than by luck.
- **"High-severity" appears verbatim in the Genie instructions** as `severity_band IN ('severe','catastrophic')`. It is the product's stated point of view, and Genie must never improvise a dollar threshold for the phrase. `claim_amount` remains available for user-stated thresholds; bands complement raw amounts rather than replacing them.
- **Claims carry one settled amount.** No incurred-versus-paid development in MVP; severity derives from the single final figure. Stated so nobody models claim development the demo does not need.
- **Severity is computed once and denormalised.** `next_claim_severity` on `policy_change_event` must come from the same code path and cuts as `severity_band` on `claim_event`. A mismatch between the change-side and claim-side view of one claim would surface directly in the evidence panel.
- **Utilisation follows the no-sentinel rule.** NULL when the limit is NULL or zero. Values above 100% are permitted and documented — clamping would hide exactly the near-limit stories the axis exists to tell. `at_or_near_limit` is `limit_utilization_pct >= 90`, a named constant.
- **The axes stay independent because their conjunction is the point.** A moderate-band claim at 98% of a recently raised limit is the signature investigation story, and it only exists if Genie can filter both columns together. At least one deterministic scenario exploits this, and the control population includes high-utilisation claims with no preceding change so the pattern reads as noteworthy rather than damning.
